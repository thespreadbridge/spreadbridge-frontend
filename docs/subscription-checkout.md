# 토스 월 구독 연결 (2026-10-26)

백엔드 `e875041`과 홈페이지 `8905157`이 최초 구현이다. 이전 요금제 문서/초기 홈페이지 검수 보고서의 "별도 결제 사이트/PG 미구현/API 대기"는 이 작업 이전 상태다. 실제 토스 상점 키 등록과 토스 테스트 결제 검증은 코드 구현·가상 PG 검증과 구분한다.

- `/payments/checkout/?plan=BASE_5&addons=0`: 로그인한 OWNER가 서버의 새 견적을 확인한다. URL의 금액이나 과거 quotedAt으로 청구하지 않는다. 카드 등록 후에도 별도 동의와 결제 버튼이 필요하다.
- `/payments/billing/callback/`: 카드 등록만 완료한다. authKey/customerKey/session은 GA와 개발 요청 로그에서 제외하고 주소에서 제거한다. 결제 화면으로 돌아가 다시 확인한다. 콜백과 결제 페이지는 noindex이고 공개 sitemap에 넣지 않는다.
- `/payments/`: 마스킹 카드/자동결제 상태, 원장 처리 상태, 결제별 환불액, 회원 즉시 해지, 해지·환불 이력을 표시한다. 상태를 조회해 접수와 승인/권한 반영/환불 완료를 구분한다.
- `/api/member/subscription/billing/[[...path]]`: 같은 출처의 인증된 OWNER 요청만 서버 API로 전달한다. Bearer/토스 시크릿 키/빌링키는 브라우저에 보내지 않는다. 장시간 PG 승인은 worker가 처리하고 BFF 주문·해지는 202를 반환한다.
- 신규 구독·업그레이드는 HMAC quoteToken과 idempotencyKey, 금액 확인/자동결제 동의를 제출한다. 사용자의 반복 클릭·응답 유실로 다른 키의 청구를 새로 만들지 않는다. 동일 작업 상태는 operation ID로 조회한다.
- 환불 예정액은 `PER_RECEIPT_KST_V1`와 각 배분·합계·기간을 검증한 경우만 표시한다. 해지 당일 제외, 각 실제 승인금액과 이용기간, 합산 후 1회 절사, 접수일 고정은 서버가 계산한다. 0원 변경/마지막 날 환불도 지원한다.
- 토스 거래가 연결되지 않은 기존 외부 영수증은 자동 환불했다고 표시하지 않는다. 서버가 거부하며 고객센터 경로를 유지한다.
- API의 `SUBSCRIPTION_BILLING_ENABLED`와 계약된 토스 개별 연동 키가 준비되어야 checkoutUrl이 열린다. 운영은 live 키를 요구한다. 격리된 로컬 API 검증에서만 127.0.0.1 HTTP 결제 주소를 허용하고 공개 API를 사용하는 환경에서는 HTTPS만 허용한다.

로컬 검증: 실제 Nest API/AuthGuard/서명 세션/일회용 PostgreSQL과 가상 토스 HTTP 서버를 사용해 5슬롯 가입 → 15슬롯 변경 → 추가 슬롯 구매(16슬롯) → 즉시 해지/203,032원 배분 환불 완료 표시까지 확인했다. 실제 토스 카드 인증·실제 돈의 거래를 검증한 결과가 아니다. 테스트용 브라우저 세션·DB·서버는 정리했다.
